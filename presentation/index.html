Zero Hardcoded Credentials

Secure 2-Tier App with CyberArk Conjur OSS

This demo shows how to deploy a production-grade application on Kubernetes where no password ever appears in source code, manifests, or environment variables.

Stack

GKE · Conjur OSS · Flask · MySQL 8 · NGINX Ingress

Auth method

Kubernetes JWT authenticator — pod identity is the credential

Secret delivery

CyberArk Secrets Provider sidecar (Push-to-File pattern)

k8s Secrets for credentials

Zero — all DB passwords live in Conjur

Both pods authenticate to Conjur using their Kubernetes service account JWT. Conjur validates the JWT against the GKE OIDC issuer, checks the pod identity, and returns the secrets. No service account keys, no API keys, no passwords in manifests.

03 / 05

Authentication with Conjur

The Secrets Provider sidecar handles the entire auth flow transparently:

1
Pod starts — Kubernetes automatically mounts a signed JWT at /var/run/secrets/kubernetes.io/serviceaccount/token
2
Sidecar POSTs JWT to Conjur: POST /authn-jwt/k8s-cluster/myConjurAccount/host%2Fmyapp%2Fwebapp/authenticate
3
Conjur validates the JWT signature against GKE's OIDC JWKS endpoint, checks the namespace and service account annotations match the policy
4
Conjur returns secrets — sidecar writes /conjur/secrets/secrets.env to a shared in-memory volume
5
App reads secrets.env — connects to MySQL. The password never appears anywhere else.

04 / 05

Challenges & Trade-offs

Challenge: JWT claim format

GKE JWTs nest service account info under kubernetes.io. Conjur's token-app-property only reads top-level claims. Solution: use URL-based identity (host in the request URL) instead of JWT claim extraction.

Challenge: Self-signed cert

Conjur uses a self-signed cert in-cluster. The sidecar needs the cert injected as a k8s secret. On cluster migrations the old cert must be refreshed — handled automatically by the Seed workflow.

Challenge: MySQL init chicken-and-egg

MySQL needs the root password at startup before Conjur can deliver it. Solution: Secrets Provider init container + MYSQL_ROOT_PASSWORD_FILE env var — MySQL reads from a file, not an env var.

Trade-off: Sidecar complexity

The Push-to-File sidecar pattern adds an init container to every pod. Benefit: zero Conjur SDK in application code. The app just reads a file. db.py is 60 lines with no Conjur dependency.
