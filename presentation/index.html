securetask namespace

Hosts the application workloads: Incident Tracker (Flask), MySQL 8, and the nginx static server (landing + presentation). Service account webapp is permitted to read DB credentials from Conjur.

conjur namespace

Hosts Conjur OSS (backed by PostgreSQL) and the Admin UI. Conjur is cluster-internal only — never exposed externally. Service account conjur-ui is permitted to read the same secrets.

03 / 06 — Conjur OSS Installation & JWT Authentication Flow

Installation & Authentication

How Conjur is installed and how pods authenticate

Installation (automated via GitHub Actions)

1 — NGINX Ingress

Installed via Helm with a LoadBalancer service. Provides the single external IP for all routes.

2 — Conjur OSS via Helm

Deployed to the conjur namespace with:
• authn,authn-jwt/k8s-cluster authenticators enabled
• A random 256-bit data encryption key stored as a k8s Secret
• ClusterIP service — no external access

3 — Account initialisation

conjurctl account create runs once inside the pod. Admin API key is captured and stored as conjur-admin-api-key Secret.

4 — TLS cert distribution

The Conjur self-signed TLS cert is extracted and stored as conjur-ssl-cert in the securetask namespace so the sidecar can verify the Conjur endpoint.

JWT Authentication Flow (per pod startup)

1
Kubernetes mounts a signed JWT Every pod automatically receives a service account token at /var/run/secrets/kubernetes.io/serviceaccount/token. This token is the pod's cryptographic identity — no password needed.
2
Secrets Provider sidecar authenticates to Conjur The sidecar POSTs the JWT to Conjur's authn-jwt endpoint: POST /authn-jwt/k8s-cluster/myConjurAccount/host%2Fmyapp%2Fwebapp/authenticate
3
Conjur validates the JWT against GKE's OIDC JWKS Conjur calls GKE's JWKS endpoint to verify the token signature, then checks the policy: is this service account in the correct namespace with the correct annotations? If yes — access granted.
4
Secrets written to a shared in-memory volume Conjur returns the permitted secrets. The sidecar writes /conjur/secrets/secrets.env to a shared emptyDir volume. The main container reads this file — never an environment variable, never a k8s Secret.
5
Application starts with credentials in memory Flask reads secrets.env, connects to MySQL, and starts serving. Credentials exist only in process memory — never on disk, never in logs.
04 / 06 — Conjur Configuration

Conjur Configuration

Policies, variables, and identity-based access control

Policy Structure (3 files, loaded via pipeline)

root.yml

Top-level branches: creates myapp policy namespace, loads child policies, grants the authn-jwt webservice.

database.yml

Declares all secrets under myapp/database/: host, port, user, name, password, root-password.
Declares host identities for webapp and conjur-ui.
Grants read permits per identity.

authn-jwt.yml

Configures the authn-jwt/k8s-cluster webservice.
Sets JWKS URL (GKE OIDC endpoint), token TTL, issuer, and audience.
Binds host identity to k8s namespace + service account.

Host Identity Binding

- !host myapp/webapp
  annotations:
    authn-jwt/k8s-cluster/kubernetes.io/namespace: securetask
    authn-jwt/k8s-cluster/kubernetes.io/serviceaccount: webapp

The JWT claim kubernetes.io/serviceaccount must match exactly. No wildcard, no shared identity — every workload has its own host entry.

Manual Workflows (Cluster Lifecycle)

conjur-install.yml

Run once on a fresh cluster. Installs NGINX Ingress + Conjur OSS via Helm, initialises the account, stores the admin key, distributes the TLS cert.

conjur-seed.yml

Loads all 3 policy files via Conjur CLI, then writes all database secrets. Idempotent — safe to re-run. Root password is generated once and never rotated automatically.

SBOM — Software Bill of Materials

Every CD run generates two SPDX JSON files (one per image) listing every OS package and Python dependency with its version and license. Downloadable from the Actions artifacts panel. Enables instant CVE impact assessment when a new vulnerability is disclosed — without rescanning.

What to Improve

🔄

Secret rotation

Conjur holds the credentials but rotation is still manual. Add automated rotation using Conjur's rotation providers or a CronJob that updates the Conjur variable and triggers a rolling restart of the affected pods.

🔐

TLS end-to-end

Current setup uses plain HTTP from the ingress to pods. Add cert-manager + Let's Encrypt (or GCP-managed TLS) to terminate HTTPS at the ingress and use TLS internally for MySQL connections.

🔑

Workload Identity Federation (no kubeconfig secret)

The CD pipeline uses a KUBECONFIG_B64 GitHub secret. Replace with GCP Workload Identity Federation so GitHub Actions authenticates directly via OIDC — no static credentials in GitHub Secrets at all.

📊

Observability

No centralised metrics or alerting. Add Prometheus + Grafana (or GCP Cloud Monitoring) with alerts on Conjur authentication failures, secret fetch errors, and pod restart counts.

🏛️

Policy as Code governance

Conjur policy changes currently require manual review. Implement OPA/Gatekeeper admission policies and require a two-person approval workflow for any change to Conjur access policies via PR review gates.
