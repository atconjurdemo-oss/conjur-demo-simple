02 / 07 — Applications Overview

Two Applications, One Secret Store

Incident Tracker and Conjur Admin UI — both consume secrets from Conjur

Incident Tracker — /app

Flask + MySQL 8 — a realistic 2-tier app.

Tracks security incidents with severity levels (Critical / High / Medium / Low), status workflow (Open → Investigating → Resolved), and structured JSON logging.

DB credentials are never in the manifest, never in env vars, never in the image. They arrive via the Conjur sidecar at pod startup.

Conjur Admin UI — /ui

Flask dashboard built to make the secrets layer visible.

Shows live: policies, variables and their values, all resources, and Conjur's own audit log filtered to security events.

Why it matters: without it, Conjur is a black box to the interviewer. With it, you can show secrets being fetched in real time.

03 / 07 — Authentication to Conjur

JWT Authentication Flow

Pod identity is the credential — no API keys, no passwords in manifests

1
Kubernetes mounts a signed JWT on every pod At startup, the kubelet automatically injects a service account token at /var/run/secrets/kubernetes.io/serviceaccount/token. This is the pod's cryptographic identity — signed by GKE's OIDC issuer.
2
Secrets Provider init container POSTs the JWT to Conjur POST /authn-jwt/k8s-cluster/myConjurAccount/host%2Fmyapp%2Fwebapp/authenticate
The sidecar sends the JWT as the request body with no additional credentials.
3
Conjur validates against GKE's OIDC JWKS endpoint Conjur fetches GKE's public keys and verifies the JWT signature. Then checks the policy: does namespace securetask + serviceaccount webapp match a known host identity? If yes — access granted.
4
Conjur returns a short-lived access token The sidecar uses this token to fetch the permitted secrets via the REST API.
5
Secrets written to shared in-memory volume Sidecar writes /conjur/secrets/secrets.env to an emptyDir medium: Memory volume. Never touches disk. The main container reads this file — never an env var, never a k8s Secret.

Policy binding — host identity to k8s workload

- !host
  id: myapp/webapp
  annotations:
    authn-jwt/k8s-cluster/kubernetes.io/namespace: securetask
    authn-jwt/k8s-cluster/kubernetes.io/serviceaccount/name: webapp
04 / 07 — Conjur Configuration

Conjur Policy Structure

Three policy files, loaded via the Conjur Seed workflow

root.yml

Creates top-level branches: myapp and authn-jwt. Grants the JWT webservice access to validate tokens.

database.yml

Declares 6 variables under myapp/database/. Declares host identities for webapp and conjur-ui. Grants read permits per identity — least privilege enforced.

authn-jwt.yml

Configures authn-jwt/k8s-cluster webservice. Sets GKE JWKS URL, issuer, audience. Grants authenticate permission to both host identities.

Installation — fully automated via GitHub Actions

conjur-install workflow

Installs NGINX Ingress + Conjur OSS via Helm. Creates account. Pushes admin key to GitHub Secrets. Distributes TLS cert to securetask.

conjur-seed workflow

Loads all 3 policy files. Configures JWT authenticator with live GKE OIDC URL. Writes all 6 database secrets. Idempotent — safe to re-run.

06 / 07 — Security Posture & Roadmap

What to Improve

Honest gaps and a clear roadmap

🔄

Automated secret rotation

Currently the init container reads secrets once at pod startup. Switch to container-mode: sidecar with secrets-refresh-interval: 30s so secrets.env stays current. Add connection pool rebuild on auth error in db.py for zero-downtime rotation without pod restarts.

🔑

GCP Workload Identity Federation for the pipeline

The CD pipeline uses a KUBECONFIG_B64 GitHub Secret — a static credential. Replace with GCP WIF so GitHub Actions authenticates via OIDC with no static keys anywhere in the pipeline.

🔐

Dedicated read-only Conjur UI operator account

The UI currently logs in as admin. A conjur-ui-operator user with read-only permits on variables (no policy management) would enforce least privilege. Policy is already written in conjur-policy/ui-operator.yml.

🏛️

Network policies + TLS end-to-end

Add Kubernetes NetworkPolicy to enforce namespace isolation. Add cert-manager + Let's Encrypt for HTTPS at the ingress and TLS for MySQL connections.

📊

Observability

Prometheus + Grafana with alerts on Conjur authentication failures, secret fetch errors, and pod restart counts.

Demo with kubectl

Prove zero hardcoded credentials — live on the cluster

1. Show secrets are in Conjur, not k8s

# No DB password in k8s Secrets
kubectl get secrets -n securetask
kubectl get secrets -n conjur

# The only credential-related secret
kubectl -n conjur get secret conjur-admin-api-key

2. Show sidecar fetched secrets at startup

# Init container ran and exited successfully
kubectl -n securetask get pod -l app=webapp
kubectl -n securetask logs <webapp-pod> -c conjur-secrets-provider

# Secrets file exists in memory volume (not on disk)
kubectl -n securetask exec <webapp-pod> -- cat /conjur/secrets/secrets.env

3. Show JWT authentication in Conjur audit log

# Open Conjur UI -> Audit Log tab
# Or check Conjur pod logs directly
kubectl -n conjur logs deployment/conjur-oss -c conjur-oss | \
  grep "authenticate" | tail -10

kubectl -n securetask get pods
curl http://<INGRESS-IP>/app/healthz

# Create an incident via the UI, verify it's stored in MySQL

  mysql -u appuser -p<password> securetask -e "SELECT * FROM incidents;"
